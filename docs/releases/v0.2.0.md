# Release Notes v.0.2.0

`v.0.2.0` переводит КарьеРадар с файлового хранения результатов на PostgreSQL и добавляет историю профилей и подборов.

### Что вошло в релиз

- Добавлен PostgreSQL 17 в Docker Compose.
- Реализованы SQLAlchemy 2.0 модели только через `Mapped` и `mapped_column`.
- Добавлены таблицы профилей, запусков поиска, вакансий и результатов выдачи.
- Настроены связи между профилем, историей поисков и найденными вакансиями.
- Добавлена дедупликация вакансий в базе по внешней ссылке.
- Профиль сохраняется вместе с нормализованными полями, исходным JSON и текстом резюме.
- Поисковые запросы, фильтры, статистика и результат LLM-фильтрации сохраняются в PostgreSQL.
- CSV исключён из серверного процесса поиска и фильтрации.
- CSV оставлен как пользовательский экспорт, формируемый в памяти на frontend.
- Обновлены API-контракты: вместо путей к файлам используются `profile_id` и `search_id`.
- Добавлены Alembic-миграции и их автоматическое применение при старте backend.
- Backend и frontend ожидают готовности PostgreSQL перед запуском.
- Добавлен отдельный async-коннектор frontend к PostgreSQL.
- Интерфейс Streamlit разделён на страницы `Новый подбор`, `Профили` и детальную страницу профиля.
- На странице профилей отображаются имя, позиции последнего поиска и сокращённое описание.
- На детальной странице отображаются полный профиль, поисковый запрос, дата последнего подбора и последняя выдача.
- Добавлена кнопка `Подобрать вакансии снова`.
- Обработаны таймауты, пустые ответы OpenRouter и нестабильные типы данных от LLM.
- Исправлено формирование имён загруженных файлов.

### Цель релиза

Главная цель `v.0.2.0` — перейти от одноразового файлового сценария к постоянному хранению данных и повторному использованию профилей кандидатов.

Релиз должен обеспечить:

- сохранение профиля после анализа резюме;
- хранение истории поисков и результатов фильтрации;
- повторный подбор вакансий без повторной загрузки резюме;
- просмотр сохранённых профилей и последних результатов через UI;
- отказ от CSV как внутреннего формата обмена между агентами.

### Изменение потока данных

```text
резюме -> профиль в PostgreSQL -> запуск поиска -> вакансии в PostgreSQL
       -> LLM-фильтрация -> сохранённая выдача -> просмотр / экспорт CSV
```

### Что пока не входит в релиз

- Авторизация и регистрация пользователей.
- Разграничение доступа к профилям и истории поисков.
- Редактирование профиля кандидата перед повторным поиском.
- Удаление и архивирование профилей через UI.
- Просмотр полной истории всех подборов одного профиля.
- Настройка источников вакансий из интерфейса.
- Расширенная аналитика по вакансиям и динамике подборов.
- Автоматическая отправка откликов работодателям.
- Production-ready мониторинг, резервное копирование и управление секретами.

### Статус релиза

`v.0.2.0` сохраняет полный MVP-сценарий первой версии и добавляет постоянное хранилище, историю подборов и повторное использование профилей.
